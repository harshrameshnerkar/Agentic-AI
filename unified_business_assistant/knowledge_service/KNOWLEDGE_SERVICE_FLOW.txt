1. SYSTEM OVERVIEW & CORE MISSION
================================================================================

The Knowledge Service (Role A) is an enterprise-grade Retrieval-Augmented 
Generation (RAG) platform. Its core responsibilities are:

  1. INGESTION & OCR:
     Automatically discover, parse, extract, and OCR (for scanned pages) 50 real
     corporate policy PDFs from 5 major enterprise organizations:
     - Susan Electricals
     - Jayaswal Neco Industries
     - Reckitt Benckiser
     - Google / Alphabet
     - GitLab

  2. DUAL-STORAGE SYSTEM:
     - Cloud SQL Store (Neon Serverless PostgreSQL): Stores text chunks with 
       gapless serial numbers (sr_no 1..N), page-level provenance, content 
       hashes for idempotent re-runs, and full audit chat telemetry.
     - Local Vector Store (ChromaDB): Stores dense vector embeddings using local
       ONNX models (all-MiniLM-L6-v2) for sub-second offline vector similarity.

  3. RETRIEVAL & RANK FUSION:
     Implements domain-aware multi-query expansion across 6 enterprise domains
     (HR, Governance, Supply Chain, POSH, CSR, IT) combined with Reciprocal Rank
     Fusion (RRF) and a calibrated 75%+ relevance threshold barrier.

  4. ANSWER SYNTHESIS & AUDIT:
     Synthesizes structured answers with exact source document and page citations.
     Uses a 3-tier model strategy:
       Tier 1: Google Gemini 2.0 Flash (Free API)
       Tier 2: Groq Cloud LLM (qwen/qwen3.8-27b / Llama-3.3)
       Tier 3: Local Offline Extractive Synthesizer (Zero external dependencies)
     Every interaction is asynchronously audited to Neon PostgreSQL.

4.1 NEON POSTGRESQL: TABLE `rag_documents`
--------------------------------------------------------------------------------
Stores all ingested text chunks with guaranteed sequential numbering and provenance.

Column Name       Type           Constraints     Description
--------------------------------------------------------------------------------
sr_no             SERIAL         PRIMARY KEY     Strictly sequential 1..N (gapless)
chunk_id          VARCHAR(100)   UNIQUE NOT NULL E.g., 'doc_001_p1_c01'
chunk_text        TEXT           NOT NULL        Full text excerpt of the chunk
source_name       VARCHAR(255)   NOT NULL        Filename (e.g. 'posh_policy.pdf')
page_number       INT            NOT NULL        1-based page number in the PDF
score_confidence  FLOAT          DEFAULT NULL    Calibrated score if precomputed
embedding_model   VARCHAR(100)   NOT NULL        E.g., 'all-MiniLM-L6-v2'
created_at        TIMESTAMPTZ    CURRENT_TIMESTAMP Insertion timestamp

Indexes:
- idx_rag_docs_source   ON rag_documents(source_name)
- idx_rag_docs_chunk_id ON rag_documents(chunk_id)


4.2 NEON POSTGRESQL: TABLE `rag_chat_logs`
--------------------------------------------------------------------------------
Maintains conversational telemetry, audit trail, and multi-turn session history.

Column Name       Type           Constraints     Description
--------------------------------------------------------------------------------
id                SERIAL         PRIMARY KEY     Auto-incrementing log ID
session_id        VARCHAR(100)   NOT NULL        Conversation identifier
user_query        TEXT           NOT NULL        User input question
bot_response      TEXT           NOT NULL        Synthesized assistant answer
sources_cited     TEXT           DEFAULT ''      E.g., 'posh.pdf:p3, ethics.pdf:p7'
confidence_score  FLOAT          DEFAULT NULL    Average confidence (0.0 to 1.0)
created_at        TIMESTAMPTZ    CURRENT_TIMESTAMP Timestamp of turn

Indexes:
- idx_chat_session      ON rag_chat_logs(session_id)

5. PROCESS FLOW 1: DOCUMENT INGESTION & DUAL-STORE SYNCHRONIZATION
================================================================================

Trigger : Executing `python 1_ingestion_pipeline.py`
Goal    : Turn 50 raw PDFs into clean, searchable, synchronized records in Neon & Chroma.

Step 1: Path Resolution & Environment Load
  File     : 1_ingestion_pipeline.py
  Function : get_paths()
  Action   : Locates data/documents, data/documents_metadata.json, and db/chroma_db.

Step 2: PDF Parsing and OCR Extraction
  File     : extraction.py
  Function : extract_all(docs_dir, meta_path, enable_ocr=True, write_report=True)
  Detailed Logic:
    1. Reads metadata catalog via load_metadata().
    2. Iterates over all 50 PDFs in alphanumeric order.
    3. Attempts text extraction page-by-page using pypdf.PdfReader.
    4. If extracted text is fewer than MIN_TEXT_CHARS (20 characters):
       a. Computes cache key using _cache_key(path, page) [hash of size + mtime].
       b. Checks data/ocr_cache.json.
       c. If miss, calls _ocr_page(pdf_path, page_idx):
          - Uses pypdfium2 to render PDF page bitmap at OCR_RENDER_SCALE (2.5x).
          - Converts bitmap to RGB numpy array.
          - Passes array to RapidOCR ONNX engine (_get_ocr()).
          - Extracts ordered text lines.
          - Caches result in ocr_cache.json.
    5. Returns List[PageText] where each item represents 1 page with metadata.
    6. Writes extraction_report.json summarizing page counts and OCR stats.

Step 3: Page-Aware Chunking
  File     : extraction.py
  Function : chunk_pages(pages, chunk_size=500, chunk_overlap=75)
  Detailed Logic:
    1. Uses LangChain RecursiveCharacterTextSplitter with separators:
       ["\n\n", "\n", ". ", " ", ""].
    2. Chunks each page independently (NEVER crosses page boundaries, preserving
       strict page provenance).
    3. Assigns deterministic Chunk ID: f"{doc_id}_p{page}_c{chunk_index:02d}".
    4. Returns List[Chunk] objects (~1,500 - 2,000 total policy chunks).

Step 4: Embedding Model Selection
  File     : 1_ingestion_pipeline.py
  Function : get_embedding_function()
  Action   : Probes for valid OPENAI_API_KEY. If absent, initializes local
             all-MiniLM-L6-v2 via chromadb.utils.embedding_functions.DefaultEmbeddingFunction.

Step 5: Cloud PostgreSQL Synchronization (Neon)
  File     : 1_ingestion_pipeline.py -> neon_client.py
  Functions: sync_to_neon(chunks, embedding_model_name)
             NeonDBClient.sync_chunks(chunks, embedding_model_name)
  Detailed Logic:
    1. Calls NeonDBClient.create_table_if_not_exists() to ensure DDL exists.
    2. Fetches existing chunk IDs and MD5 hashes:
       "SELECT chunk_id, md5(chunk_text) AS h FROM rag_documents;"
    3. Identifies:
       - stale chunks   (in DB but no longer in source) -> deleted via _delete_chunk_ids()
       - changed chunks (content hash mismatch)         -> deleted and re-inserted
       - new chunks     (not present in DB)             -> batched for insertion
       - unchanged      -> skipped (idempotent, 0 cost)
    4. Batches inserts into rag_documents (50-100 chunks/batch) via HTTP SQL API.
    5. Calls resequence_serial_numbers():
       Uses SQL CTE with ROW_NUMBER() OVER (ORDER BY source_name, page_number, chunk_id)
       to guarantee gapless sequential sr_no (1, 2, 3... N).

Step 6: Vector Store Indexing (ChromaDB)
  File     : 1_ingestion_pipeline.py
  Function : update_vector_store(chunks, embedding_func, db_path)
  Detailed Logic:
    1. Initializes chromadb.PersistentClient at db/chroma_db/.
    2. Gets or creates collection "rag_documents" with cosine distance.
    3. Identifies unindexed chunk IDs.
    4. Batches vector upserts: collection.upsert(ids, documents, metadatas).

6. PROCESS FLOW 2: FORMAL ROLE A SEARCH API (POST /search)
================================================================================

Trigger : HTTP Client calls POST http://127.0.0.1:8000/search
Payload : {"question": "What is the POSH grievance procedure?", "top_k": 5}
Contract: Defined in contracts.py & UNIFIED-BUSINESS-ASSISTAN.md §3.4

Step 1: API Endpoint Handling & Validation
  File     : app.py
  Function : search_documents(payload: SearchRequest)
  Action   : Validates input with Pydantic; delegates to engine.search().

Step 2: Multi-Query Domain Expansion
  File     : rag_engine.py
  Function : UnifiedRAGEngine.expand_queries(query: str)
  Action   : Inspects keywords and generates synthetic expansion queries across
             the 6 corporate policy domains (e.g., adding "Prevention of Sexual
             Harassment workplace policy internal complaints committee redressal").

Step 3: Vector Similarity Search
  File     : rag_engine.py
  Function : UnifiedRAGEngine.search(question, top_k, score_threshold)
  Action   :
    1. Executes self.collection.query() across all expanded queries.
    2. Requests top_k * 3 candidate chunks for each variation.
    3. Computes raw cosine similarity: raw_similarity = 1.0 - distance.

Step 4: Score Calibration & Reciprocal Rank Fusion (RRF)
  File     : rag_engine.py
  Function : UnifiedRAGEngine.calibrate_score(raw_score: float)
  Action   :
    - Raw MiniLM cosine similarities range between 0.30 and 0.70.
    - calibrate_score() maps raw values to an intuitive 0.0 - 1.0 confidence:
        calibrated = (raw_score - 0.28) / (0.68 - 0.28)
    - Applies Reciprocal Rank Fusion: rrf = 1.0 / (60 + rank).
    - Aggregates multiple hits for the same chunk by taking max confidence and summing RRF.

Step 5: Threshold Filtering & Deduplication
  File     : rag_engine.py
  Action   :
    - Enforces calibrated score_threshold barrier (default 0.75, i.e. 75%+ relevance).
    - Deduplicates snippets by hashing the first 100 normalized characters.
    - Limits final list to requested top_k passages.

Step 6: Return Response
  File     : app.py
  Output   : SearchResponse(results=[PassageResult(...)], no_match=bool, embedding_model=str)

7. PROCESS FLOW 3: CONVERSATIONAL RAG & CHATBOT API (POST /chat)
================================================================================

Trigger : User sends a message via Web Dashboard (static/index.html) or REST API
Payload : {"message": "What about paternity leave?", "session_id": "sess_123"}

Step 1: API Route Entry
  File     : app.py
  Function : conversational_chat(payload: ChatRequest)
  Action   : Calls engine.chat().

Step 2: Small Talk & Conversational Guard
  File     : rag_engine.py
  Function : UnifiedRAGEngine.chat(...)
  Action   :
    - Checks for greetings ("hi", "hello", "who are you") or thank-yous ("thanks", "got it").
    - If detected: logs to Neon and immediately returns self-introduction or appreciation
      response WITHOUT wasting vector search or LLM compute.

Step 3: Chat History Retrieval
  File     : neon_client.py
  Function : NeonDBClient.get_chat_history(session_id, limit=4)
  Action   : Queries Neon SQL for previous user queries and bot responses in this session.

Step 4: History-Aware Query Reformulation
  File     : rag_engine.py
  Function : UnifiedRAGEngine.contextualize_question(question, history)
  Action   :
    - If question is dependent (e.g. contains "what about", "it", "they", or < 4 words):
      Option A (Cloud LLM): Calls free Gemini/Groq prompt to re-write query into standalone query.
      Option B (Rule-based): Extracts keywords from last user query and appends context:
                             "What about paternity leave? regarding parental leave policy".
    - Resolves standalone query for downstream retrieval.

Step 5: Document Retrieval with 75%+ Barrier
  File     : rag_engine.py
  Function : UnifiedRAGEngine.search(standalone_question, top_k, score_threshold=0.75)
  Action   :
    - If no passages pass the 75%+ threshold:
      Returns standard out-of-scope response:
      "I do not have sufficient information meeting the 75%+ confidence matching threshold..."
      Logs to Neon and exits early.

Step 6: Structured Prompt Assembly
  File     : rag_engine.py
  Action   : Formats retrieved passages into clean context blocks with source, page,
             company, and confidence rating.

Step 7: 3-Tier Multi-Model Answer Generation
  File     : rag_engine.py
  Function : UnifiedRAGEngine._call_llm_free(user_prompt, system_prompt)
  Tier Sequence:
    1. Google Gemini 2.0 Flash:
       Calls Google Generative Language REST API (zero extra dependencies).
    2. Groq Cloud (Fallback):
       Uses Groq OpenAI-compatible client with model 'qwen/qwen3.8-27b' or 'llama-3.3'.
    3. Local Free Extractive Engine (Offline Fallback):
       No API keys required! Scans passages for direct policy definitions ("means",
       "is defined as", "shall include") or extracts high-salience excerpt sentences.

Step 8: Citation Construction & Audit Telemetry
  File     : rag_engine.py -> neon_client.py
  Function : NeonDBClient.log_chat_interaction(...)
  Action   :
    1. Formats clean citations list with source file, page, chunk_id, company, and score.
    2. Computes average confidence score.
    3. Writes session_id, user_query, bot_response, sources_cited, and score to Neon
       PostgreSQL table `rag_chat_logs`.

Step 9: Return Chat Response
  File     : app.py
  Output   : ChatResponse(session_id, question, standalone_question, answer, citations, model_used, no_match)

11. FIRST-TIME DEVELOPER ONBOARDING CHEAT SHEET
================================================================================

Q1: "How do I run the whole service locally?"
  1. Install dependencies:
     pip install -r requirements.txt
  2. Verify .env contains:
     DATABASE_URL=postgresql://user:password@endpoint.neon.tech/neondb?sslmode=require
  3. Start the server:
     python app.py
  4. Open in browser:
     http://127.0.0.1:8000 (Interactive Chatbot UI)
     http://127.0.0.1:8000/docs (Interactive Swagger API documentation)

Q2: "How do I add or update a policy document?"
  1. Place the new PDF into: `data/documents/<new_policy>.pdf`
  2. Add an entry with metadata to: `data/documents_metadata.json`
  3. Run the ingestion pipeline:
     python 1_ingestion_pipeline.py
  * The pipeline is idempotent: it will only extract and embed the NEW document!
    Existing documents are preserved and serial numbers are cleanly updated.

Q3: "Where are embeddings stored and how do they work?"
  - Stored in local directory: `db/chroma_db/`
  - Computed using `all-MiniLM-L6-v2` via Chroma's built-in ONNX runtime.
  - Requires NO GPUs, NO external API calls, NO costs, and runs completely offline.

Q4: "Where are database records and chat logs stored?"
  - Stored in Neon Serverless PostgreSQL.
  - Chunks live in table: `rag_documents`
  - Chat conversations live in table: `rag_chat_logs`
  - Access is executed via HTTPS SQL endpoint (no persistent connection pool exhaustion).

Q5: "How do I test a query without running the web server?"
  - Quick retrieval check:
    python retrieval_pipeline.py "What is the POSH committee procedure?"
  - Full answer generation check:
    python answer_generation.py "What is the parental leave duration?"

Q6: "How do I verify the system meets all requirements?"
  - Run the automated test suite:
    python evaluate_e2e.py
