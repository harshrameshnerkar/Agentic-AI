## 1. What is a Virtual Environment (`venv`)?
In Python, packages installed via `pip install` by default go into a global system directory.
- **Problem**: Project A requires `pydantic v1.10`, while Project B requires `pydantic v2.4`. Installing one overwrites the other, breaking dependencies globally!
- **Solution**: A **virtual environment** (`.venv`) creates an isolated folder containing its own Python executable and separate `site-packages/` directory.

### Commands:
```bash
# 1. Create a virtual environment named .venv
python -m venv .venv

# 2. Activate on Windows PowerShell:
.venv\Scripts\Activate.ps1

# (Or Windows CMD: .venv\Scripts\activate.bat)
# (Or Linux/macOS: source .venv/bin/activate)

# 3. Confirm active Python interpreter:
python -c "import sys; print(sys.executable)"
```

## 2. Managing Dependencies with `pip`
Instead of manually typing install commands every time, define them in `requirements.txt`:
```txt
openai>=1.40.0
anthropic>=0.30.0
google-genai>=0.1.1
python-dotenv>=1.0.0
```
Install all dependencies with one command:
```bash
pip install -r requirements.txt
```

## 3. Storing Keys in `.env` & Never Hardcoding Keys
### Why Hardcoding Keys is Dangerous:
1. **GitHub Scraping**: Public repositories are constantly scraped by malicious bots within seconds of a commit.
2. **Account Abuse**: Leaked keys result in thousands of dollars in unauthorized API usage.
3. **Environment Mismatch**: Staging, testing, and production environments require different credentials.

### Best Practice Architecture:
1. Create a `.env` file (stored locally, **never committed** to git):
   ```ini
   OPENAI_API_KEY=sk-proj-...
   ANTHROPIC_API_KEY=sk-ant-...
   GEMINI_API_KEY=AIzaSy...
   ```
2. Add `.env` to `.gitignore`:
   ```gitignore
   .env
   .venv/
   __pycache__/
   ```
3. Provide `.env.example` as a template for team members without real secrets.
4. Load secrets at runtime using `python-dotenv`:
   ```python
   from dotenv import load_dotenv
   import os

   load_dotenv() # Reads key-value pairs from .env and injects into os.environ
   api_key = os.getenv("OPENAI_API_KEY")
   ```

## 4. Making the First API Call: Chat Completion Architecture
LLMs are stateless HTTP REST APIs. You send an array of message objects:
```json
[
  {"role": "system", "content": "You are a concise AI tutor."},
  {"role": "user", "content": "Explain what an LLM API is."}
]
```

### Roles:
- `system`: Directs behavior, personality, output constraints, and tone.
- `user`: The user's input/query.
- `assistant`: Past AI responses (used for multi-turn conversational context).

### Hyperparameters:
- `temperature`: `0.0` to `2.0`. Lower values (e.g. `0.2`) are deterministic and factual; higher values (e.g. `0.8`) are creative and varied.
- `max_tokens`: The maximum number of tokens the model is allowed to generate.

## 5. Deconstructing the Response Object
When the provider returns a response, it contains rich metadata:

```json
{
  "id": "chatcmpl-9Abc123xyz890",
  "object": "chat.completion",
  "created": 1728118800,
  "model": "gpt-4o-mini-2024-07-18",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "An LLM API is a cloud-based interface..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 28,
    "completion_tokens": 42,
    "total_tokens": 70
  }
}
```

### Key Fields:
| Field | Purpose |
|---|---|
| `id` | Unique request identifier for logging and debugging. |
| `choices[0].message.content` | The actual text generated by the model. |
| `choices[0].finish_reason` | `stop` (completed naturally) or `length` (hit max_tokens cap). |
| `usage.prompt_tokens` | Tokens in system prompt + user question (input cost). |
| `usage.completion_tokens` | Tokens generated by the model (output cost). |
| `usage.total_tokens` | Total tokens billed (`prompt_tokens + completion_tokens`). |
